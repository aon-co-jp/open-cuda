**شروع توسعه: 2026-06-26** (تاریخ ایجاد این مخزن در GitHub)

«دومین CUDA» — یک بنیاد انتزاع/محاسبات GPU (طراحی `OmniGPU`) که هدف آن
سازگاری با Windows/macOS/Linux و Intel/AMD/NVIDIA است. جفت‌شده
(«SET») با `aruaru-llm`، که مصرف‌کننده پیاده‌سازی خط لوله اجرای GPU/CPU
است.

## این چیست

- **`opencuda-core`**: صفت (trait) `GpuDevice` مشترک میان همه
  بک‌اندها (معادل CUDA Runtime API: `alloc`/`memcpy`/`launch_kernel`).
- **`opencuda-cpu`**: بک‌اند CPU (موازی‌سازی داده از طریق `rayon`).
- **`opencuda-vulkan`**: بک‌اند Vulkan Compute (چندسکویی، بومی روی
  Windows/Linux/Android، macOS/iOS از طریق MoltenVK). GEMM/Attention/
  کوانتیزاسیون INT4·INT8 روی اجرای واقعی Vulkan تأیید شده‌اند.
- **`opencuda-directx`** (افزوده‌شده در 2026-07-23): یک بک‌اند
  DirectX 12 Compute (فقط Windows، بک‌اندی اختیاری که هم‌زمان با
  Vulkan وجود دارد). ارسال GPU برای `vector_add`/`matmul`/`ChaCha20`
  روی سخت‌افزار واقعی (NVIDIA GT 730) تأیید شده — خروجی دقیقاً با
  پیاده‌سازی‌های مرجع CPU (مثلاً crate `chacha20` از RustCrypto) در
  تست‌ها مطابقت دارد. دریافت نام واقعی سازنده/ظرفیت VRAM از طریق
  شمارش آداپتورهای DXGI نیز پیاده‌سازی شده است.
- **`opencuda-blas`**: معادل NumPy (GEMM/Attention/کوانتیزاسیون).
- **`open-cuda-bert`**: گذر رو به جلو برای رمزگذارهای خانواده BERT
  (از multilingual-e5-small پشتیبانی می‌کند).
- **`open-cuda-llm`**: معادل vLLM (رمزگشایی حریصانه با کش KV).
  `GptModel::load` را پیاده‌سازی می‌کند که `safetensors` مربوط به
  GPT-2 (Hugging Face `openai-community/gpt2`) را بارگذاری می‌کند
  (2026-07-25، همان طراحی `open-cuda-bert::BertModel::load`). روی
  سخت‌افزار واقعی تأیید شده: دانلود و بارگذاری وزن‌های واقعی GPT-2
  124M انگلیسی رمزگشایی‌شده حریصانه‌ای به‌مراتب روان‌تر از مقداردهی
  اولیه تصادفی (خروجی بی‌معنا) تولید می‌کند — مثلاً "The quick brown
  fox" → "es are a great way to get a little bit of a". برای جزئیات به
  HANDOFF در `CLAUDE.md` مراجعه کنید.
- **`open-cuda-whisper`** (افزوده‌شده در 2026-07-31): معادل Whisper
  (تشخیص گفتار، رتبه #۶ در نقشه راه تحقیقات بازار). استخراج
  log-mel-spectrogram + رمزگذار (همان طراحی Multi-Head Attention
  `open-cuda-bert`) + رمزگشای دارای کش KV (همان طراحی
  `open-cuda-llm`) + cross-attention. **در حال حاضر فقط یک MVP با
  مقداردهی اولیه تصادفی** (هنوز بارگذارِ وزن‌های آموزش‌دیده Whisper
  وجود ندارد — برای جزئیات به HANDOFF در `CLAUDE.md` مراجعه کنید).

## چرا هم DirectX و هم Vulkan داریم (تصمیم فنی مورخ 2026-07-23)

در ابتدا تصور می‌شد این پروژه «به‌عنوان افزونه DirectX در حال توسعه»
است. پس از تأیید این موضوع از طریق جستجوی وب به ژاپنی/انگلیسی، مشخص شد
که DXVK/vkd3d-proton (فناوری‌ای که Proton شرکت Valve واقعاً از آن
استفاده می‌کند) هر دو در جهت «DirectX (رابط برنامه‌نویسی فقط ویندوز)
→ Vulkan (رابط برنامه‌نویسی چندسکویی)» تبدیل می‌کنند — نمونه‌ای از جهت
معکوس یافت نشد. **برای هدف پشتیبانی چندسکویی، رویکرد Vulkan Compute
موجود از نظر فنی مسیر مستقیم‌تری است.** بر این اساس، سیاست «نگه‌داشتن
Vulkan و افزودن DirectX برای Windows به‌صورت هم‌زیستی» اتخاذ شد و
`opencuda-directx` پیاده‌سازی شد.

## افشای صادقانه

- **پشتیبانی چندسکویی همچنان در حال پیشرفت است**: Vulkan Compute برای
  پشتیبانی بومی روی Windows/Linux/Android و پشتیبانی مبتنی بر MoltenVK
  روی macOS/iOS طراحی شده، اما تأیید روی سخت‌افزار واقعی فقط روی این
  دستگاه (Windows، NVIDIA GT 730) انجام شده است.
- **ارسال هسته‌های `opencuda-directx` تنها بخشی از فاز ۲ را پوشش
  می‌دهد**: `vector_add`، `matmul` و `ChaCha20` (فقط رمزگذاری — شامل
  محاسبه تگ احراز هویت Poly1305 نمی‌شود) پیاده‌سازی شده‌اند. تشخیص
  سازنده از طریق شمارش آداپتورهای DXGI (`GpuVendor::Nvidia` و غیره) نیز
  پیاده‌سازی شده، اما اطلاعات جزئی مانند `compute_capability` همچنان
  یک placeholder است زیرا از DXGI قابل دریافت نیست.
- **سود واقعی فشرده‌سازی/رمزگذاری روی GPU تأیید نشده است**: برای
  بار داده‌ای کوچک مانند یک فریم تونل، این نگرانی فنی وجود دارد که
  سربار انتقال میزبان↔دستگاه ممکن است مزیت محاسباتی GPU را خنثی کند
  (محک‌زنی واقعی همچنان کاری برای آینده است).

### آن را روی GPU خودتان امتحان کنید (افزوده‌شده در 2026-07-27)

اگر فقط می‌خواهید ابتدا یک چیز را اجرا کنید تا مطمئن شوید کار می‌کند،
هر زیر-crate در `examples/` (عضوی از فضای کاری) را می‌توان با
`cargo run -p <نام>` اجرا کرد. به‌ویژه `vulkan_info` نمونه‌ای حداقلی
است که فقط دستگاه‌های فیزیکی واقعی Vulkan (نام سازنده GPU، ظرفیت VRAM)
را روی دستگاه شما شمارش و چاپ می‌کند، که آن را به بهترین اولین دستور
برای بررسی اینکه آیا GPU در محیط شما شناسایی می‌شود تبدیل می‌کند:

```bash
cargo run -p vulkan_info
```

نمونه‌های دیگر (`matmul`، `matmul_vulkan_real`، `vector_add`،
`vector_add_vulkan`، `vector_add_vulkan_real`، `vector_add_omniir`) را
نیز می‌توان به همین ترتیب با `cargo run -p <نام>` اجرا کرد. برای ماتریس
وضعیت پشتیبانی به تفکیک سازنده (Intel/AMD/NVIDIA و غیره) به
`OmniGPU-Design.md` بخش ۸.۵ مراجعه کنید.
