# open-cuda — Руководство по переносу (сокращённая версия)

> **Примечание**: это сокращённый перевод актуальных
> переиспользуемых паттернов. Подробный исторический журнал HANDOFF
> остаётся доступен только на японском в [PORTING.md](PORTING.md) —
> сверяйтесь с ним перед фактическим применением паттерна.

Сводка переиспользуемых архитектурных паттернов этого проекта — на
случай переноса в другой проект.

1. **Трейт `GpuDevice` (дизайн, независимый от бэкенда)**: минимальный
   контракт в духе CUDA Runtime API (`alloc`/`free`/`memcpy_h2d`/
   `memcpy_d2h`/`memcpy_d2d`/`launch_kernel`/`synchronize`) плюс
   флаги возможностей (`supports_spirv`/`supports_dxil`, по
   умолчанию `false`). Новые аппаратные бэкенды реализуют этот
   контракт и расширяют перечисление `KernelSource` без разрушения
   совместимости (например, `Dxil(Vec<u8>)`).
2. **Двухэтапный паттерн «мок → реальное железо»**: Фаза 1
   (мок-устройство, работает без железа, проверяет контракты даже в
   CI без GPU), Фаза 1.5–2 (реальная реализация за Cargo-фичей, по
   умолчанию выключена, честно пропускает себя при отсутствии
   реального железа).
3. **Ловушка выравнивания массивов в HLSL cbuffer**: скалярные
   массивы в `cbuffer` выравниваются по границе 16 байт — плотно
   упакованные константы Rust/C++ перестают совпадать с раскладкой
   HLSL (реально вызвало баг «вывод остаётся открытым текстом» в
   ядре ChaCha20). Решение: отдельные скалярные поля (`key0`…
   `key7`) вместо объявления массива.
4. **Root signature, встроенная в HLSL**: атрибут
   `[RootSignature(...)]`, написанный прямо в шейдере, заставляет
   `dxc` встроить root signature в DXIL — избавляет от ручного
   построения дескриптора root signature в коде Rust/C++. Прямая
   привязка root UAV дескрипторов вместо descriptor heap.
5. **Перечисление адаптеров DXGI для определения производителя**:
   `D3D12CreateDevice(None, ...)` не даёт информации о производителе
   и объёме VRAM. `IDXGIFactory1::EnumAdapters1(0)` →
   `DXGI_ADAPTER_DESC1` даёт PCIe vendor ID (NVIDIA/AMD/Intel). При
   сбое безопасно откатываться к `None`.
6. **Честное предупреждение о сжатии/шифровании на GPU**: для
   небольших payload (размер сетевого MTU) накладные расходы на
   передачу Host↔Device могут свести на нет вычислительное
   преимущество GPU — перед интеграцией провести реальные
   бенчмарки на целевом размере payload.
7. **Паттерн ядер чётности RAID6**: переменное число дисков с
   данными как один сцепленный буфер (вместо отдельных привязок на
   диск). Умножение в GF(2^8) для Q-parity (Рид-Соломон) как
   самостоятельная функция `gf_mul` (умножение «по-русски»,
   неприводимый многочлен `0x11D`) внутри шейдера.
8. **Реализация на GPU без зависимости от 64-битных целых**:
   64-битные целые — опциональная аппаратная фича в DXIL SM6.0.
   Poly1305 реализует парное умножение/сложение/сдвиг 32×32→64 бита
   только на 32-битных операциях — паттерн для переноса
   криптографии/больших чисел на цели без гарантии 64-бит.
9. **Сжатие KV-кэша в стиле MLA от DeepSeek-V3**: down-/up-проекция
   на основе существующей `sgemm`. **Честное раскрытие**: матрицы
   проекции инициализированы только случайно (без обученных весов)
   — сжатие с потерями; это доказывает лишь корректность
   вычислительного пути, а не сохранение качества генерации.
10. **Штраф за повторения (в стиле CTRL)**: `logit>0` → `/penalty`,
    `logit<=0` → `*penalty`, применяется к уже встреченным токенам
    перед argmax. `penalty=1.0` — короткий путь, точно сохраняющий
    существующее поведение `generate()` (без регрессий).
    Эмпирическое значение по умолчанию `1.3` — требует
    перекалибровки под структуру промпта.

**Текущее состояние**: Cargo workspace из `opencuda-core`/
`opencuda-cpu`/`opencuda-vulkan`/`opencuda-directx`/`opencuda-blas`/
`open-cuda-bert`/`open-cuda-llm`. `opencuda-directx` реализован до
Фазы 2 (vector_add/matmul/ChaCha20/Poly1305 проверены на реальном
железе). Ядра чётности RAID6 P/Q добавлены в `opencuda-vulkan`,
проверены на реальном железе. Подробности — в записях HANDOFF в
[CLAUDE.md](CLAUDE.md).
