> **Останнє оновлення (2026-08-10)**: До `open-cuda-llm::GptModel`
> додано `generate_with_repetition_penalty` (штраф за повторення у
> стилі CTRL — penalty>1.0 послаблює логіти вже виведених токенів).
> Наявний `generate()` тепер є тонкою обгорткою, що викликає його з
> `penalty=1.0` (побайтово ідентична поведінка, без регресій для
> наявних тестів/викликачів). Це напряму усуває задокументовану ваду в
> `aruaru-llm`, коли базовий GPT-2 (без діалогового донавчання) під час
> жадібного декодування нескінченно повторює той самий рядок (наприклад,
> "Student: Hello"). Додано новий тест на реальних вагах GPT-2 124M,
> `repetition_penalty_reduces_degenerate_loop_on_real_gpt2_weights`, що
> підтверджує: без штрафу цикл дійсно відтворюється, а при
> `penalty=1.3` дійсно припиняється (утворюючи граматично природний
> текст). `/v1/generate` в `aruaru-llm` тепер за замовчуванням викликає
> цей новий API з `penalty=1.3` (перевизначається через
> `ARUARU_LLM_REPETITION_PENALTY`). Див. запис HANDOFF від 2026-08-10 у
> [CLAUDE.md](CLAUDE.md).

> **Останнє оновлення (2026-08-08)**: Повторно перевірено на реальному

> (`cargo test -p opencuda-blas mla -- --nocapture` → `1 passed; 0

> щільний FFN (без структури експертів/маршрутизатора), і реального
> чекпоінту MoE не існує. Деталі див. у записі HANDOFF від 2026-08-08 у

**Початок розробки: 2026-06-26** (дата створення цього репозиторію на
GitHub)

«Другий CUDA» — основа абстракції/обчислень GPU (дизайн `OmniGPU`),
що прагне до сумісності з Windows/macOS/Linux та Intel/AMD/NVIDIA.
Складає пару («SET») з `aruaru-llm`, яка є споживачем-реалізацією
конвеєра виконання GPU/CPU.

## Що це таке

- **`opencuda-core`**: Трейт `GpuDevice`, спільний для всіх бекендів
  (еквівалент CUDA Runtime API: `alloc`/`memcpy`/`launch_kernel`).
- **`opencuda-cpu`**: Бекенд CPU (паралелізм даних через `rayon`).
- **`opencuda-vulkan`**: Бекенд Vulkan Compute (крос-платформний,
  нативно на Windows/Linux/Android, macOS/iOS через MoltenVK). GEMM/
  Attention/квантування INT4·INT8 перевірені на реальному виконанні
  Vulkan.
- **`opencuda-directx`** (додано 2026-07-23): Бекенд DirectX 12
  Compute (лише Windows, опційний бекенд, що співіснує з Vulkan).
  Диспетчеризація GPU для `vector_add`/`matmul`/`ChaCha20` перевірена
  на реальному обладнанні (NVIDIA GT 730) — вивід точно збігається з
  еталонними реалізаціями CPU (наприклад, крейт RustCrypto `chacha20`)
  у тестах. Також реалізовано отримання реального імені виробника/
  обсягу VRAM через перелічення адаптерів DXGI.
- **`opencuda-blas`**: Еквівалент NumPy (GEMM/Attention/квантування).
- **`open-cuda-bert`**: Прямий прохід для енкодерів родини BERT
  (підтримує multilingual-e5-small).
- **`open-cuda-llm`**: Еквівалент vLLM (жадібне декодування з KV-кешем).
  Реалізує `GptModel::load`, що завантажує `safetensors` GPT-2
  (Hugging Face `openai-community/gpt2`) (2026-07-25, той самий дизайн,
  що й `open-cuda-bert::BertModel::load`). Перевірено на реальному
  обладнанні: завантаження реальних ваг GPT-2 124M дає явно плавнішу
  жадібно декодовану англійську мову, ніж випадкова ініціалізація
  (безглуздий вивід) — наприклад, "The quick brown fox" → "es are a
  great way to get a little bit of a". Деталі див. у HANDOFF файлу
  `CLAUDE.md`.
- **`open-cuda-whisper`** (додано 2026-07-31): Еквівалент Whisper
  (розпізнавання мовлення, #6 у дорожній карті маркетингового
  дослідження). Видобування лог-мел-спектрограми + енкодер (той самий
  дизайн Multi-Head Attention, що й `open-cuda-bert`) + декодер з
  KV-кешем (той самий дизайн, що й `open-cuda-llm`) + cross-attention.
  **Наразі лише MVP з випадковою ініціалізацією** (завантажувача
  навчених ваг Whisper ще немає — деталі див. у HANDOFF `CLAUDE.md`).

## Чому в нас є і DirectX, і Vulkan (технічне рішення від 2026-07-23)

Спочатку вважалося, що цей проєкт «розробляється як плагін DirectX».
Після перевірки за допомогою веб-пошуку японською та англійською мовами
з'ясувалося, що DXVK/vkd3d-proton (технологія, яку справді використовує
Proton від Valve) обидва конвертують у напрямку «DirectX (API лише для
Windows) → Vulkan (крос-платформний API)» — прикладів зворотного
напрямку знайдено не було. **Для мети крос-платформної підтримки
наявний підхід Vulkan Compute технічно є прямішим шляхом.** На основі
цього було прийнято політику «зберегти Vulkan і додатково додати
DirectX для Windows, що співіснує», і було реалізовано
`opencuda-directx`.

## Чесне розкриття інформації

- **Крос-платформна підтримка перебуває в процесі розробки**: Vulkan
  Compute спроєктовано для нативної підтримки на Windows/Linux/Android
  та підтримки на основі MoltenVK на macOS/iOS, але перевірка на
  реальному обладнанні виконувалася лише на цій машині (Windows, NVIDIA
  GT 730).
- **Диспетчеризація ядер `opencuda-directx` покриває лише частину
  Фази 2**: реалізовано `vector_add`, `matmul` та `ChaCha20` (лише
  шифрування — не включає обчислення тега автентифікації Poly1305).
  Також реалізовано визначення виробника через перелічення адаптерів
  DXGI (`GpuVendor::Nvidia` тощо), але детальна інформація, така як
  `compute_capability`, залишається заглушкою, оскільки не може бути
  отримана з DXGI.
- **Реальна вигода від стиснення/шифрування на GPU не перевірена**:
  для такого маленького корисного навантаження, як один кадр тунелю,
  існує технічне занепокоєння, що накладні витрати на передачу між
  хостом і пристроєм можуть звести нанівець обчислювальну перевагу GPU
  (реальне тестування продуктивності залишається майбутнім завданням).

```bash
cargo build --workspace

# Тести на реальному обладнанні DirectX 12 (лише Windows, функція real-dx12)
cargo test -p opencuda-directx --features real-dx12
```

### Спробуйте на власному GPU (додано 2026-07-27)

Якщо ви просто хочете спочатку запустити щось одне, щоб переконатися,
що це працює, кожен суб-крейт у `examples/` (член робочого простору)
можна запустити за допомогою `cargo run -p <ім'я>`. Зокрема,
`vulkan_info` — це мінімальний приклад, що просто перелічує та виводить
реальні фізичні пристрої Vulkan (ім'я виробника GPU, обсяг VRAM) на
вашій машині, що робить його найкращою першою командою для перевірки,
чи виявляється GPU у вашому середовищі:

```bash
cargo run -p vulkan_info
```

Інші приклади (`matmul`, `matmul_vulkan_real`, `vector_add`,
`vector_add_vulkan`, `vector_add_vulkan_real`, `vector_add_omniir`)
аналогічно можна запускати за допомогою `cargo run -p <ім'я>`. Див.
`OmniGPU-Design.md` §8.5 для матриці стану підтримки за виробниками
(Intel/AMD/NVIDIA тощо).
