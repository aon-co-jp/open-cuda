## Роль цього проєкту

«Другий CUDA» — основа абстракції/обчислень GPU (дизайн `OmniGPU`, див.
`OmniGPU-Design.md`), що прагне до сумісності з Windows/macOS/Linux та
Intel/AMD/NVIDIA. Утворює «SET» з `aruaru-llm`, яка є реальним
споживачем конвеєра виконання GPU/CPU.

## Архітектура крейтів

- **`opencuda-core`**: спільний трейт `GpuDevice` (еквівалент CUDA
  Runtime API).
- **`opencuda-cpu`**: бекенд CPU (паралелізм даних через `rayon`).
- **`opencuda-vulkan`**: крос-платформний бекенд Vulkan Compute
  (нативно на Windows/Linux/Android, macOS/iOS через MoltenVK). GEMM/
  Attention/квантування INT4·INT8 перевірені на реальному обладнанні.
- **`opencuda-directx`**: бекенд DirectX 12 Compute (лише Windows,
  співіснує з Vulkan). Диспетчеризація ядер vector_add/matmul/
  ChaCha20/Poly1305 перевірена на реальному обладнанні (GT 730);
  реалізовано перелічення адаптерів DXGI для визначення виробника/VRAM.
- **`opencuda-blas`**: еквівалент NumPy (GEMM/Attention/квантування/
  Flash Attention/стиснення KV MLA).
- **`open-cuda-bert`**: прямий прохід для енкодерів BERT
  (multilingual-e5-small).
- **`open-cuda-llm`**: еквівалент vLLM — декодер GPT-2 з KV-кешем,
  штрафом за повторення, стисненням MLA, flash attention та
  (найновіша функція) спекулятивним декодуванням.
- **`open-cuda-whisper`**: еквівалент Whisper (лог-мел-спектрограма +
  енкодер + декодер з KV-кешем + cross-attention), наразі лише MVP з
  випадковою ініціалізацією.

## Чесний стан розкриття інформації

- **cuBLAS/rocBLAS/oneMKL залишаються неперевіреними заглушками** — на
  цій машині немає інструментарію CUDA/ROCm/oneAPI для перевірки.
- **FP8 відхилено**: єдиний GPU цієї машини (GT730, Kepler, CC 3.5) не
  має Tensor Cores для FP8 — реалізація була б чистою програмною
  емуляцією без реальної користі.
- **DeepSeekMoE відхилено**: `DecoderLayer` має лише один щільний FFN
  (без структури експертів/маршрутизатора), і реального чекпоінту MoE
  не існує.
- **Стиснення/шифрування на GPU**: реальна вигода для малих корисних
  навантажень не перевірена (накладні витрати хост↔пристрій можуть
  звести нанівець перевагу GPU).
- **Знахідка на реальному Android-пристрої (2026-08-15)**: на
  Android-пристрої (moto g53y 5G, Adreno 619) GPU телефону перевершив
  як CPU, так і порівняння CPU/GPU настільної GT730 при більших
  розмірах матриць (до ~6× при 512×512), підтвердивши гіпотезу, що
  «GPU телефонів можуть бути на диво швидкими». Застереження:
  одноразові невеликі обчислення все ще обмежені накладними витратами
  ініціалізації GPU (58–63мс).

## Матриця підтримки виробників

Три рівні: працююча інтеграція Vulkan / перелічення `GpuVendor` як
рівень лише для звітності (включно з неперевіреними Qualcomm/ARM/
ImaginationPowerVr) / рівень заглушок бібліотек виробників. Деталі у
`OmniGPU-Design.md` §8.5.

## Нещодавні актуальні записи HANDOFF

- **2026-08-10**: `generate_with_repetition_penalty` (штраф за
  повторення у стилі CTRL) усуває реальну помилку нескінченного циклу
  в жадібному декодуванні GPT-2 в `aruaru-llm`. Значення за
  замовчуванням `penalty=1.3` через `ARUARU_LLM_REPETITION_PENALTY`.
- **Найновіша робота (коміт `0c43ba3`)**: Новий
  `GptModel::generate_speculative` — безвтратне спекулятивне
  декодування у стилі DSpark/Leviathan (чорнова модель пропонує
  токени, цільова модель перевіряє через пакетний batch-prefill).
  Перевірено як побітово ідентичне `generate()` на синтетичних
  фікстурах та реальних вагах. **Чесне розкриття**: на шляху CPU цієї
  машини повільніше за звичайний `generate()` (draft_k=4: plain 4,63с
  проти спекулятивного 7,65с), оскільки наївний CPU GEMM має мало
  накладних витрат на диспетчеризацію для амортизації. Реальний
  цільовий сценарій — швидкість на реальному Vulkan — поки не
  виміряно.
