## Роль этого проекта

«Второй CUDA» — основа абстракции/вычислений GPU (дизайн `OmniGPU`, см.
`OmniGPU-Design.md`), нацеленная на совместимость с
Windows/macOS/Linux и Intel/AMD/NVIDIA. Образует «SET» с `aruaru-llm`,
которая является реальным потребителем конвейера исполнения GPU/CPU.

## Архитектура крейтов

- **`opencuda-core`**: общий трейт `GpuDevice` (эквивалент CUDA Runtime
  API).
- **`opencuda-cpu`**: бэкенд CPU (параллелизм данных через `rayon`).
- **`opencuda-vulkan`**: кроссплатформенный бэкенд Vulkan Compute
  (нативно на Windows/Linux/Android, macOS/iOS через MoltenVK). GEMM/
  Attention/квантование INT4·INT8 проверены на реальном оборудовании.
- **`opencuda-directx`**: бэкенд DirectX 12 Compute (только Windows,
  сосуществует с Vulkan). Диспетчеризация ядер vector_add/matmul/
  ChaCha20/Poly1305 проверена на реальном оборудовании (GT 730);
  реализовано перечисление адаптеров DXGI для определения
  производителя/VRAM.
- **`opencuda-blas`**: эквивалент NumPy (GEMM/Attention/квантование/
  Flash Attention/сжатие KV MLA).
- **`open-cuda-bert`**: прямой проход для энкодеров BERT
  (multilingual-e5-small).
- **`open-cuda-llm`**: эквивалент vLLM — декодер GPT-2 с KV-кэшем,
  штрафом за повторение, сжатием MLA, flash attention и (самая новая
  функция) спекулятивным декодированием.
- **`open-cuda-whisper`**: эквивалент Whisper (лог-мел-спектрограмма +
  энкодер + декодер с KV-кэшем + cross-attention), в настоящее время
  только MVP со случайной инициализацией.

## Честный статус раскрытия информации

- **cuBLAS/rocBLAS/oneMKL остаются непроверенными заглушками** — на
  этой машине нет инструментария CUDA/ROCm/oneAPI для проверки.
- **FP8 отклонён**: единственный GPU этой машины (GT730, Kepler,
  CC 3.5) не имеет Tensor Cores для FP8 — реализация была бы чистой
  программной эмуляцией без реальной пользы.
- **DeepSeekMoE отклонён**: `DecoderLayer` имеет лишь один плотный FFN
  (без структуры экспертов/маршрутизатора), и реального чекпоинта MoE
  не существует.
- **Сжатие/шифрование на GPU**: реальная выгода для маленьких полезных
  нагрузок не проверена (накладные расходы хост↔устройство могут
  свести на нет преимущество GPU).
- **Находка на реальном Android-устройстве (2026-08-15)**: на
  Android-устройстве (moto g53y 5G, Adreno 619) GPU телефона превзошёл
  как CPU, так и сравнение CPU/GPU настольной GT730 при больших
  размерах матриц (до ~6× при 512×512), подтвердив гипотезу о том, что
  «GPU телефонов могут быть на удивление быстрыми». Оговорка:
  разовые небольшие вычисления по-прежнему ограничены накладными
  расходами инициализации GPU (58–63мс).

## Матрица поддержки производителей

Три уровня: работающая интеграция Vulkan / перечисление `GpuVendor`
как уровень только для отчётности (включая непроверенные Qualcomm/
ARM/ImaginationPowerVr) / уровень заглушек библиотек производителей.
Подробности в `OmniGPU-Design.md` §8.5.

## Недавние актуальные записи HANDOFF

- **2026-08-10**: `generate_with_repetition_penalty` (штраф за
  повторение в стиле CTRL) устраняет реальную ошибку бесконечного
  цикла в жадном декодировании GPT-2 в `aruaru-llm`. Значение по
  умолчанию `penalty=1.3` через `ARUARU_LLM_REPETITION_PENALTY`.
- **Самая последняя работа (коммит `0c43ba3`)**: Новый
  `GptModel::generate_speculative` — безлоссовое спекулятивное
  декодирование в стиле DSpark/Leviathan (черновая модель предлагает
  токены, целевая модель проверяет через пакетный batch-prefill).
  Проверено как побитово идентичное `generate()` на синтетических
  фикстурах и реальных весах. **Честное раскрытие**: на пути CPU этой
  машины медленнее, чем обычный `generate()` (draft_k=4: plain 4,63с
  против спекулятивного 7,65с), поскольку наивный CPU GEMM имеет мало
  накладных расходов на диспетчеризацию для амортизации. Реальный
  целевой сценарий — скорость на реальном Vulkan — пока не измерен.
