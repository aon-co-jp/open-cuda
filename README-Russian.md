«Второй CUDA» — основа абстракции/вычислений GPU (дизайн `OmniGPU`),
нацеленная на совместимость с Windows/macOS/Linux и
Intel/AMD/NVIDIA. Составляет пару («SET») с `aruaru-llm`, которая
является потребителем-реализацией конвейера исполнения GPU/CPU.

## Что это такое

- **`opencuda-core`**: Трейт `GpuDevice`, общий для всех бэкендов
  (эквивалент CUDA Runtime API: `alloc`/`memcpy`/`launch_kernel`).
- **`opencuda-cpu`**: Бэкенд CPU (параллелизм данных через `rayon`).
- **`opencuda-vulkan`**: Бэкенд Vulkan Compute (кроссплатформенный,
  нативно на Windows/Linux/Android, macOS/iOS через MoltenVK). GEMM/
  Attention/квантование INT4·INT8 проверены на реальном выполнении
  Vulkan.
- **`opencuda-directx`** (добавлено 2026-07-23): Бэкенд DirectX 12
  Compute (только Windows, опциональный бэкенд, сосуществующий с
  Vulkan). Диспетчеризация GPU для `vector_add`/`matmul`/`ChaCha20`
  проверена на реальном оборудовании (NVIDIA GT 730) — вывод точно
  совпадает с эталонными реализациями CPU (например, крейт RustCrypto
  `chacha20`) в тестах. Также реализовано получение реального имени
  производителя/объёма VRAM через перечисление адаптеров DXGI.
- **`opencuda-blas`**: Эквивалент NumPy (GEMM/Attention/квантование).
- **`open-cuda-bert`**: Прямой проход для энкодеров семейства BERT
  (поддерживает multilingual-e5-small).
- **`open-cuda-llm`**: Эквивалент vLLM (жадное декодирование с KV-кэшем).
  Реализует `GptModel::load`, который загружает `safetensors` GPT-2
  (Hugging Face `openai-community/gpt2`) (2026-07-25, тот же дизайн, что
  и `open-cuda-bert::BertModel::load`). Проверено на реальном
  оборудовании: скачивание и загрузка реальных весов GPT-2 124M даёт
  явно более плавный жадно декодированный английский текст, чем
  случайная инициализация (бессмысленный вывод) — например, "The quick
  brown fox" → "es are a great way to get a little bit of a". Подробности
  см. в HANDOFF файла `CLAUDE.md`.
- **`open-cuda-whisper`** (добавлено 2026-07-31): Эквивалент Whisper
  (распознавание речи, #6 в дорожной карте маркетингового исследования).
  Извлечение лог-мел-спектрограммы + энкодер (тот же дизайн Multi-Head
  Attention, что и `open-cuda-bert`) + декодер с KV-кэшем (тот же
  дизайн, что и `open-cuda-llm`) + cross-attention. **В настоящее время
  только MVP со случайной инициализацией** (загрузчика обученных весов
  Whisper пока нет — подробности см. в HANDOFF `CLAUDE.md`).

## Почему у нас есть и DirectX, и Vulkan (техническое решение от 2026-07-23)

Изначально считалось, что этот проект «разрабатывается как плагин
DirectX». После проверки с помощью веб-поиска на японском и английском
языках выяснилось, что DXVK/vkd3d-proton (технология, которую
действительно использует Proton от Valve) оба конвертируют в
направлении «DirectX (API только для Windows) → Vulkan (кроссплатформенный
API)» — примеров обратного направления найдено не было. **Для цели
кроссплатформенной поддержки существующий подход Vulkan Compute
технически является более прямым путём.** На основе этого была принята
политика «сохранить Vulkan и дополнительно добавить DirectX для
Windows, сосуществующий», и был реализован `opencuda-directx`.

## Честное раскрытие информации

- **Кроссплатформенная поддержка находится в процессе разработки**:
  Vulkan Compute спроектирован для нативной поддержки на
  Windows/Linux/Android и поддержки на основе MoltenVK на macOS/iOS, но
  проверка на реальном оборудовании выполнялась только на этой машине
  (Windows, NVIDIA GT 730).
- **Диспетчеризация ядер `opencuda-directx` покрывает лишь часть
  Фазы 2**: реализованы `vector_add`, `matmul` и `ChaCha20` (только
  шифрование — не включает вычисление тега аутентификации Poly1305).
  Также реализовано определение производителя через перечисление
  адаптеров DXGI (`GpuVendor::Nvidia` и т.д.), но подробная информация,
  такая как `compute_capability`, остаётся заглушкой, поскольку не
  может быть получена из DXGI.
- **Реальная выгода от сжатия/шифрования на GPU не проверена**: для
  такой маленькой полезной нагрузки, как один кадр туннеля, существует
  техническое опасение, что накладные расходы на передачу между хостом
  и устройством могут свести на нет вычислительное преимущество GPU
  (реальное тестирование производительности остаётся будущей задачей).

## Сборка и тестирование

```bash
cargo build --workspace
cargo test --workspace

# Тесты на реальном оборудовании DirectX 12 (только Windows, функция real-dx12)
cargo test -p opencuda-directx --features real-dx12
```

### Проверьте на собственном GPU (добавлено 2026-07-27)

Если вы просто хотите сначала запустить что-то одно, чтобы убедиться,
что это работает, каждый суб-крейт в `examples/` (член рабочего
пространства) можно запустить с помощью `cargo run -p <имя>`. В
частности, `vulkan_info` — это минимальный пример, который просто
перечисляет и выводит реальные физические устройства Vulkan (имя
производителя GPU, объём VRAM) на вашей машине, что делает его лучшей
первой командой для проверки того, обнаруживается ли GPU в вашей среде:

```bash
cargo run -p vulkan_info
```

Другие примеры (`matmul`, `matmul_vulkan_real`, `vector_add`,
`vector_add_vulkan`, `vector_add_vulkan_real`, `vector_add_omniir`)
аналогично можно запускать с помощью `cargo run -p <имя>`. См.
`OmniGPU-Design.md` §8.5 для матрицы состояния поддержки по
производителям (Intel/AMD/NVIDIA и т.д.).
